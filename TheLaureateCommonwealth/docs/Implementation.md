# Implementation and files

The Laureate Commonwealth is integrated into the existing collection, with one invisible `InGameUIAddin` simulation context and no separate setup UI. All authoritative actions are native `GameEvents` callbacks. Nothing depends on selecting the active player, clicking a UI control, animation completion or per-frame polling.

| Mechanic | Implementation |
| --- | --- |
| Identity and inheritance | Schema-derived runtime `SELECT *` copies of America/Washington identity defaults, active Swordsman and active Amphitheater. Only personality companions are copied from Washington; no American/shared traits. All replacement companion tables are inherited. Human-only selection. |
| World Wonders | CP `CityConstructed` after successful production. Check current city ownership, actual building presence and a globally limited class, excluding team/player limited classes. A save-scoped completion receipt prevents duplicate event awards. Capturing a city does not invoke this completion event. |
| Great People | CP `UnitCreated` creates a persistent candidate only for genuine `SPECIALUNIT_PEOPLE` units owned by a Laureate human. Save the creation-Era, speed-scaled amount in unit ScriptData. Delay payment until the native operation settles. `UnitConverted` cancels the new candidate and settles the source's genuine birth once. Native capture identities reject replacement GPs without consuming unrelated same-tile births. A hidden, inert lifetime promotion blocks reinitialization. `CityTrained`, `UnitPrekill` and native turn boundaries settle valid candidates. No existing unit becomes a new candidate on load. |
| Level 3 | Versioned unit ScriptData distinguishes pending native initialization, eligible low-level history, foreign/legacy threshold closure and paid recognition. The existing promotion remains the lifetime reward receipt. `UnitConverted` establishes ownership/history without awarding the incoming unit; capture replacement identity carries history across ID and level resets. `UnitPromoted` recognizes eligible progression, and one owner-turn pass catches direct level setters and insta-heal. Fresh creation remains eligible; unknown legacy high-level units cannot earn retrospective rewards. Native boundaries resolve only pending IDs; normal foreign turns never enumerate armies. |
| Real Golden Age progress | `Player:ChangeGoldenAgeProgressMeter(amount)` changes native progress in hundredths through the DLL binding. Normal threshold, no-happiness option, overflow and optional native meter restrictions remain authoritative. The engine's next normal threshold check starts a Golden Age. |
| Speed | `GreatPeoplePercent`, confirmed in `CvPlayer::GetGoldenAgeProgressThreshold`. Quick 67, Standard 100, Epic 150, Marathon 300 in the installed baseline. This differs from `GoldenAgePercent`, which scales duration and some other native rewards. |
| Golden Age bonuses | Unselectable branchless `POLICY_LC_GOLDEN_EXCELLENCE`, `IsDummy=1`, `GreatPeopleRateModifier=15`, `ExpModifier=15`, applied as a free policy. CP `PlayerGoldenAge` toggles actual possession once at start/end. Native `processPolicies` changes XP and Great Person rate caches; city specialist accumulation and combat XP read those caches. Startup/load reconciliation repairs possession from `IsGoldenAge` without activation spam. Extensions do not stack. |
| Crowning Blow | Native `AttackWoundedMod=15`, `HPHealedIfDestroyEnemy=15`. The melee attack formula requires a damaged defender; the defense formula has no wounded-attack term. Native military combat resolves the kill, caps healing to existing damage and respects cannot-heal effects. No second Lua kill handler. `LostWithUpgrade=0`; explicit conversion repair retains it through normal class changes. |
| Hall | Active Amphitheater, `Happiness=Happiness+1` (ordinary local building Happiness). Lua counts `GetNumActiveBuilding` on functioning owned cities and credits that total once at `PlayerDoTurn`. This avoids CP-only suppression of ordinary city GAP accumulation while already in a Golden Age. Resistance, razing and anarchy suppress the payout. No extra Culture, Tourism, cost, maintenance or Great Work slot. |

State uses namespaced `[LC1_...=...]` fields inside existing player/unit ScriptData without overwriting other mods' strings. Wonder receipts, Hall turn, Golden Age feedback state and pending GP amount retain their existing formats. New version-2 veteran history, native-creation candidates and source-player capture receipts survive save/context reconstruction. The existing veteran/recognized-GP promotions remain native saved lifetime receipts; no database identities or promotion IDs are added. The controller retires old handlers and rejects duplicate initialization in one context.

CP capture creation copies ScenarioData but discards level, promotions and ScriptData, and its notification provides no replacement ID. A saved identity receipt temporarily tags that native-carried integer and restores its previous value when the replacement settles. Movement capture prepares the tag before its snapshot; combat capture prepares it at Prekill before the later capture notification. Delayed deaths retain the receipt until final deletion. This removes ambiguous tile/class matching, including original-owner Prophet recapture. [Hardening](Hardening.md) documents event order, migration, tests and the shared ScenarioData compatibility requirement.

The implementation follows CP's native generation systems: the city bonus changes specialist GPP, not General/Admiral combat pools or Prophet Faith costs. Ordinary promotions use the Era when promoted. A direct scripted Level setter or insta-heal promotion has no CP level event, so the once-per-owner-turn fallback necessarily uses the Era when detected. A replacement implemented by another mod must emit the supported native conversion hook (use `Unit:Convert`) to identify itself as a replacement; arbitrary unrelated `InitUnit` and `Kill` calls contain no native link from which any mod can infer that intent. Normal CP creation, upgrade, gift, conversion and capture paths are handled.

The official source pin is `44c1e14ff75d80c1dba5c8a71e8289439a53aafb` in [Community-Patch-DLL](https://github.com/LoneGazebo/Community-Patch-DLL/tree/44c1e14ff75d80c1dba5c8a71e8289439a53aafb/CvGameCoreDLL_Expansion2). The focused validator records exact source hashes and executable checks. This verifies source contracts, not live engine acceptance.

The [complete file inventory](Files.md) lists every added or modified path. Files added:

- `SQL/00_LC_Core.sql`, `01_LC_Inheritance.sql`, `02_LC_Effects.sql`, `03_LC_Art.sql`, `10_LC_Text.sql`: identity, active replacement inheritance, native effects, atlases, complete English localization and diplomacy.
- `Lua/LC_Commonwealth.lua`, `LC_Commonwealth.xml`: simulation and entry context.
- `Art/LC_*.dds`: 40 complete mipmapped textures; `LC_LeaderScene.xml`: original static diplomacy scene.
- `README.md`, `CHANGELOG.md`, `docs/Implementation.md`, `Testing.md`, `Validation.json`: guide and evidence.
- `docs/Hardening.md`: exploit reproduction, eligibility/capture identity design, migration and hardening validation.
- `../art-source/TheLaureateCommonwealth/*` and three `IconAtlasMasters/LC_*.png`: original paintings, prompts, derived masters and visual preview.
- `../tools/generate_laureate.py`, `prepare_laureate_art.py`, `validate_laureate.py`, `tests/laureate_mock.lua`, `tests/laureate_assertions.lua`: reproducible builders and validation.
- `../docs/civilizations/TheLaureateCommonwealth.md`: roster reference page.

Shared changes: root README/changelog; `tools/build_mod.py` inventory, entry point, append-only SQL order and optional art-preserving build; `tools/standardize_icons.py` mipmap support for the new LC family; existing ModBuddy project/modinfo; `tools/validate_mod.py` focused validation dispatch. `validate_honeycomb.py` now locates its own contiguous SQL block and entry by identity so future appended civilizations do not invalidate its ordering test. No existing civ gameplay, balance, art or identity is changed.
