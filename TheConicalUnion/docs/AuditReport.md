# Conical Union reliability audit — 2026-10-25

**Assessment:** ready for native in-game acceptance testing. The automated regressions pass; native gameplay, rendering, quick-load/save lifecycle, Harbor routing and Huge-map performance remain unverified. First-settlement accuracy has **not** been improved: the verified CP v151 cached-connection timing limitation remains. Version 13, collection UUID, saved building identities and all three exact uniques are preserved.

## Issues discovered and fixed

| Classification | Issue and root cause | Implemented correction |
| --- | --- | --- |
| **Fixed — reproduced synthetically** | A shared `CONICAL_ControllerLoaded=true` survives while a newly created context has no registrations. The previous reload test cleared shared data and handlers together, hiding the failure. | Context-owned registry plus a context-private Lua global; a fresh Lua environment registers even if a native context pointer is reused. Old wrappers retire/remove, same-context includes are inert, and a late old shutdown cannot clear a new owner. Retained wrappers check active ownership if removal fails. |
| **Fixed — reproduced synthetically** | The old batch-level retry restarted an entire empire twice. A persistent setter failure in an early city prevented later healthy cities from being reconciled. | Retry separately per city and continue through the remaining cities. Per-operation diagnostics stay suppressed until recovery. |
| **Fixed — reproduced synthetically** | A failed cleanup could leave a Gold/UA marker in a foreign city. Normal foreign turns were skipped, and initialization visited only Conical owners; saving/reloading could preserve the residue. | Track failed foreign owner/city IDs only, retry them on owner turn without enumerating the foreign empire, discard vanished IDs, and sanitize each foreign city list once per context on load. |
| **Fixed — reproduced synthetically** | The old busy guard dropped every nested event, including the only dirty/ownership notification for a different city. | Ignore self-induced dirty notifications only for the city currently being reconciled. Coalesce other-city/ownership work by primitive arguments and drain it synchronously with a bounded dispatch budget. |

The shared-marker and city-batch tests were run against the committed pre-audit controller and failed with missing new-context handlers and a healthy city's missing yields. Separate pre-fix executions also reproduced unretried foreign Gold, dropped cross-city cleanup and uninspected saved foreign residue. These are code/synthetic reproductions, **not reports of native game failures**.

Primary changed implementation: `Lua/ConicalUnion.lua`. Validation changes: `tools/validate_conical_union.py`, `tools/tests/conical_mock.lua`, the existing resilience test and four new suites (`conical_context`, `conical_faults`, `conical_timing`, `conical_ownership`). Updated implementation/testing/source-inventory documentation, changelogs and generated modinfo hash accompany the change. No SQL, artwork, replacement-unit/building definition, peer gameplay or persistence format is changed.

## Connection synchronization findings

All CP references below are pinned to official commit `44c1e14ff75d80c1dba5c8a71e8289439a53aafb`, DLL version 151. Exact source URLs and digests are retained in [SourceAudit.json](SourceAudit.json).

1. [`CvPlayer::setTurnActive`](https://github.com/LoneGazebo/Community-Patch-DLL/blob/44c1e14ff75d80c1dba5c8a71e8289439a53aafb/CvGameCoreDLL_Expansion2/CvPlayer.cpp#L33713) publishes turn-start status **before** `GetCityConnections()->Update()`, then proceeds to `doTurn`. Turn-start status therefore does not provide the desired post-refresh barrier.
2. [`CvCityConnections::UpdateRouteInfo`](https://github.com/LoneGazebo/Community-Patch-DLL/blob/44c1e14ff75d80c1dba5c8a71e8289439a53aafb/CvGameCoreDLL_Expansion2/CvCityConnections.cpp#L287) calls `CityConnections` as a `TESTANY` extension query before clearing/rebuilding flags. `CityConnected` is another route query during partial network construction, before final mixed-network Capital flags. Neither is a completion notification. Mutating building state there would read stale/partial data and could interfere with native recalculation.
3. [`CvPlot::SetRoutePillaged`](https://github.com/LoneGazebo/Community-Patch-DLL/blob/44c1e14ff75d80c1dba5c8a71e8289439a53aafb/CvGameCoreDLL_Expansion2/CvPlot.cpp#L9402) stores the route-pillage flag and can emit `TileRouteChanged`; it does not refresh city connections. Route changes also omit Harbor/blockade transitions and may occur in foreign/unowned route segments. An empire scan here would not guarantee a fresh result.
4. [`CvCity::SetRouteToCapitalConnected`](https://github.com/LoneGazebo/Community-Patch-DLL/blob/44c1e14ff75d80c1dba5c8a71e8289439a53aafb/CvGameCoreDLL_Expansion2/CvCity.cpp#L7637) changes the cached flag and conditionally recalculates religion. It emits no general completion hook. An incidental `SpecificCityInfoDirty` can repair a known city but is not guaranteed at the correct point for every network change; it may accompany other work during a rebuild.
5. [`CvCity::doTurn`](https://github.com/LoneGazebo/Community-Patch-DLL/blob/44c1e14ff75d80c1dba5c8a71e8289439a53aafb/CvGameCoreDLL_Expansion2/CvCity.cpp#L2331) calls native Production settlement. [`CvPlayer::doTurnPostDiplomacy`](https://github.com/LoneGazebo/Community-Patch-DLL/blob/44c1e14ff75d80c1dba5c8a71e8289439a53aafb/CvGameCoreDLL_Expansion2/CvPlayer.cpp#L10326) runs city turns, then Gold, then Culture, and later emits `PlayerDoTurn`. `PlayerDoneTurn` is the end-of-turn phase before unit reset; it does not cause a network refresh.
6. [`CvGame::update`](https://github.com/LoneGazebo/Community-Patch-DLL/blob/44c1e14ff75d80c1dba5c8a71e8289439a53aafb/CvGameCoreDLL_Expansion2/CvGame.cpp#L1618) can resume `doTurnPostDiplomacy` before `GameCoreUpdateBegin`. That recurring core-update event is neither a universal before-settlement hook nor suitable lightweight reconciliation. `PlayerPreAIUnitUpdate` belongs to unit processing, not the refresh/settlement boundary.

**Conclusion — known engine limitation:** no reliable general after-refresh/before-Production/Gold/Culture callback was verified in this source path. Keep native cached semantics, the existing lifecycle notifications and owner-turn fallbacks; do not mutate route queries, invent pathfinding, poll core updates or grant compensating treasury yields.

The explicit `conical_timing.lua` scenario executes **old cache → end-turn reconciliation → native flag refresh → first economic settlement → PlayerDoTurn reconciliation → subsequent settlement**. On both a new connection and final break, the first settlement can use the previous dummy state; reconciliation corrects the following settlement. A supported lifecycle/targeted notification after refresh can correct it earlier. Tests cover road/railroad/Harbor/mixed/alternative-route-shaped flags. They prove binary controller behavior, **not native Harbor pathfinding**.

## Save/load and ownership findings

**Fixed lifecycle hole; native lifecycle still requires testing.** Context recreation is now independent of whether the shared registry survives. Tests cover retained shared data with discarded events, a fresh Lua environment with a reused native pointer, retained events, normal shutdown, late old shutdown, same-context inclusion, fresh shared data/new-game shapes, missing removal APIs and replacement native city/player objects. Exactly one effective controller performs work. These tests deliberately separate shared state, context identity and event registration instead of resetting them as one artificial operation.

The existing Cats controller already uses context identity; it was inspected as a local convention and left unchanged. Installed Firaxis `UI/InGame/UnitFlagManager.lua` demonstrates `ContextPtr:SetShutdown`; `Bombardment.lua` demonstrates `Events.Remove`; the New World scenario demonstrates `GameEvents.Remove`. The validator records all three local script hashes and API examples. These establish API usage, not the closed-source UI engine's exact quick-load destruction order. Native menu-load, quick-load and in-game reload remain mandatory acceptance cases.

**Verified correct:** both conditional counts are reconstructed as 0/1; no connection state, yield award, City userdata or gameplay save schema is added. Context ownership and retry queues are transient. A failed foreign cleanup is retried from IDs; load sanitation repairs persisted markers even if that transient queue was lost. `NeverCapture` is retained as a native defense, with explicit Lua cleanup as a second defense. Liberation goes through native `acquireCity`, and capture reads the newly reconstructed city by plot. Capital notifications immediately exclude a new Capital under the current native state; a former Capital becomes eligible according to its current flag. Native Walls/Detour Office capture rules remain unchanged.

**Failure limits:** native setters cannot be made atomic across two buildings. While a setter remains unavailable, a city can temporarily retain a partial pair; it is retried and repaired when the API succeeds. The failure of one city no longer blocks others. Diagnostics are bounded until recovery. A deliberately hostile reentrant storm can exceed the 32-job synchronous dispatch budget; retained work resumes on the next natural event. Normal setters' self-dirty events do not queue redundant queries or writes. No frame handler is used.

## Worker and Office audit

**Verified correct; implementation unchanged.** Road Crew continues to clone the active Worker scalar row and all supported companion rows at activation. `Moves+1` and integer `WorkRate*5/4` remain the only mechanical scalar changes. The native [`workRate` formula](https://github.com/LoneGazebo/Community-Patch-DLL/blob/44c1e14ff75d80c1dba5c8a71e8289439a53aafb/CvGameCoreDLL_Expansion2/CvUnit.cpp#L15838) scales the base by common modifiers and truncates after integer division; native build progress consumes that result. Worker build actions, automation, embarkation-related properties, free promotions, upgrades and capture class remain inherited. Capture resolves through native `GetSpecificUnitType`, with native recapture/event exceptions.

The installed backup baseline is Moves 2 / WorkRate 100; standalone installed CP v151 has no Worker/Walls balance rewrite. The available cache is not CP-activated, so this is not a live CP observation. Changed-baseline regression uses Moves 4 / WorkRate 120 and verifies 5 / 150, altered build permissions, free promotion and selection-sound companion rows, as well as a new scalar field. Ordinary Worker rows remain unchanged. A 25% progress increase is approximately 20% fewer turns before completion-turn rounding, not universally 25% fewer turns. A hypothetical non-divisible-by-four base is outside exact native integer representation and is rejected by the validator.

**Verified correct; implementation unchanged.** Detour Office retains Walls defense/HP/cost/technology/maintenance/class and every supported companion row. Culture is additive to existing Walls Culture. Changed-baseline checks alter those properties and add existing Culture/Gold yields, then compare exact inheritance. Gold requires a **real** Office, current Conical ownership, non-capital status and the single shared connection result. Removal, reconstruction, connection transitions and repeated synchronization do not stack or deliver treasury payments.
