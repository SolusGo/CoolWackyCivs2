# Final implementation audit — 2026-10-22

Audited baseline: `b28b641882e0fa04ff3320b88974d390f605cc54`. Target: Windows Civilization V BNW, Community Patch DLL v151, Lua 5.1. Fifteen relevant official source files were freshly fetched from pinned commit `44c1e14ff75d80c1dba5c8a71e8289439a53aafb` and independently inspected. Source URLs and hashes are in [SourceAudit.json](SourceAudit.json).

## Assessment and release decision

The six-building persistence format, native flat-yield design, active Worker/Market inheritance and preceding-turn preparation are retained. Two conditional runtime defects were reproduced and fixed, with no changes to SQL, balance, artwork, civilization identities, save marker encoding, mod version or UUID. The Circus remains human-only. Existing civilization gameplay/art files remain byte-identical.

**Ready for native acceptance testing; not certified for unrestricted release.** This audit did not launch Civ V. Actual economic payouts, closed-engine event delivery and native save/autosave restoration remain the release gate. There are **no confirmed CRITICAL or HIGH findings in the ordinary, error-free stock-CP path**. The conditional findings below are proven against shipped Lua in controlled simulations; they are not reports of observed native crashes or routine in-game failures.

The first finding is conditional on a unit-loss/relocation event during owner-entry/economic processing. As a source example, `CvCity::doTurn` calls `doMeltdown` after `doProduction`, and nuclear damage can kill civilians before player Gold/Culture. **The installed backup-derived baseline has no buildings with `NukeExplosionRand > 0`**, so this audit does not claim that example is enabled in a normal stock-CP game. Scripted changes or a mod enabling that native branch can exercise the ordering. The confirmed fact is the old Lua's incorrect response to that event sequence; its native frequency is unverified. No new disaster, movement or gameplay system was introduced.

## Timing and autosave trace

1. In sequential single-player, `CvGame::CheckPlayerTurnDeactivate` requires an alive active owner, end-turn/AI eligibility, processed automoves and completed activity. It calls the old owner's `setTurnActive(false)` before activating the next sequential player. `PlayerDoneTurn(int owner)` is gated by `EVENTS_PLAYER_TURN`, enabled by unchanged Circus SQL, and runs before native unit reset.
2. `setTurnActive(false)` writes the first-alive player's single-player autosave **before** the active flag changes and before PlayerDoneTurn. Its snapshot is therefore pre-preparation. Player serialization stores active/end/automove flags; processed automoves are reset, not serialized. `Read` restores active-player counts without running economic turns. In the ordinary source-traced resume path, updateMoves rebuilds processed automoves, then eligible deactivation emits the missing Done hook. The fixture now models those actual gates, including resumed movement and busy blockers. Closed-engine loading/mission cancellation must still be tested.
3. At the new owner-turn, native `m_bTurnActive` becomes true before attrition, `doTurn` and economic processing. The repaired runtime uses **both** this saved/native flag and equality with the reserved raw turn. This distinguishes owner entry from a global raw rollover while a later-slot human is still waiting. A reservation already cancelled during inactive interturn events cannot be resurrected by an active-turn dirty event.
4. City `doProduction` credits the real Production rate plus overflow. After city turns, `CvTreasury::DoGold` computes ordinary net Gold from city rates and credits the treasury, subject to native solvency/anarchy rules. Player Culture subsequently accumulates from native city Culture rates. Only later does PlayerDoTurn run. Staging at the prior Done hook supplies the first pass; a later callback records its already-begun state without resource compensation or a second award.
5. T, T+1 and T+2 receive the show. Ending T+2 removes its dummies before T+3 economics. T+11 is still ineligible; ending it with an eligible Crew stages T+12. Duplicate callbacks and setter retries cannot move absolute expiration/eligibility boundaries. Raw game turns advance once per round; no speed multiplier or elapsed-frame counter is used. Tests run at raw starts 0 and 150 and all five requested speeds.

## Save, unit, building and city findings

All six existing `BUILDING_WCIRCUS_*` identifiers and +1 encodings are unchanged. Native int counts are uncapped and serialized; IsDummy excludes normal building totals. Yield dummies are still normalized to 0/1, hidden/unbuildable/unpurchasable, maintenance-free and nontransferable. Writes use the verified no-construction-bonus argument and compare current counts first. Lua holds no authoritative timing ledger. Old valid v9 count layouts are exercised directly; no migration, reset or new save-store API is needed. A previously cancelled/missed show is not reconstructed or compensated. Actual native v9 continuation and version 8 compatibility remain untested; keep backups and avoid downgrades.

The native capture definition samples a unit's original owner, captured creation restores it, and unit serialization retains it. Captured Workers may resolve to the captor's unique Worker type. Current/original owner plus exact Carnival Crew type therefore remain checked. Originally owned recaptured Crews qualify; foreign converted Workers do not. Prekill identifies the owner/unit/type before delayed-death flagging; the still-present dying ID is excluded only in its owner's interturn validation. UnitSetXY receives owner, unit ID, x, y **after** relocation. Multiple qualifying Crews still produce one show. Native recapture/automation behavior requires acceptance despite the verified bindings and simulations.

Ticket Office keeps every active Market scalar and companion row, with additive +1 Culture and no new unconditional Production. Source checks trace real building yields to native city rates and real construction progress. Production/Gold/Culture remain ordinary base yields, with normal modifiers, integer rounding, resistance/anarchy/razing, purchases, overflow and treasury rules. Before/after-production completion/removal tests intentionally do not retroactively credit already-finished construction. Construction and gold/faith purchase events follow creation; sale follows removal. SpecificCityInfoDirty is verified from the native post-setter publisher and shipped Firaxis consumer. Generic dirty events remain a coalesced fallback.

NeverCapture rejection precedes the native nonconquest exception, covering capture, gifts and liberation. Native AcquireCity reconstructs then emits CityCaptureComplete with the fifth argument as new owner. All six states are explicitly cleared by the resolved new city plot as a second safeguard, including when a pending city is returned immediately. Founding's ABI is owner,x,y; unused arguments are safely ignored. Razing, destruction and elimination discard native city arrays; no City userdata is retained across callbacks. Unusual scripts bypassing normal native paths remain outside the verified contract.
