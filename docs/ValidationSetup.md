# Reproducing BNW / Community Patch v151 validation

The validators need game-owned files which cannot be supplied by this repository. They never write to the installed game's database or mod directory. SQL executes in an in-memory copy; a passing simulation is not native game acceptance.

## External prerequisites

- Python 3.11+ with `requirements-dev.txt`: Pillow, Lupa with its `lua51` runtime, and py7zr.
- An installed Windows Civilization V with Brave New World, including its original UI Lua/XML files.
- Community Patch **version 151**, UUID `d1b6328c-ff44-4b0d-aad7-c657f83610cd`. A differently numbered Community Patch is rejected.
- An intact **BNW** debug database snapshot without Cool Wacky Civs 2 already applied. A vanilla/non-BNW cache or a collection-populated cache is rejected; the tools never fall back to an arbitrary menu database.
- The pinned official CP sources, initialized by `audit_cp.py --fetch`. No game account or API key is needed to download public source.

## Create the database snapshot

The user data directory is normally `Documents\My Games\Sid Meier's Civilization 5`, possibly redirected into OneDrive. It is different from both this repository's `Civ5\WackyMods` path and the Steam game install.

1. Back up `config.ini`, then enable `LoggingEnabled = 1` in the game user directory.
2. In Civ V's Mods menu activate **CP v151 without either Cool Wacky Civs collection**. Use BNW and load/start an actual game. Quit the game before copying the database.
3. Copy `cache\Civ5DebugDatabase.db` to a separate snapshot file. Do not use a cache regenerated by returning to a vanilla menu. The validators check required BNW rows, CP installation version and existing collection identities before using it.
4. Set `CWC2_CIV5_CACHE` explicitly to the snapshot. By historical convention the default is `cache_backup\Civ5DebugDatabase.db`; if absent, validation stops with setup instructions rather than choosing another database.

The adapter accepts a compatible BNW snapshot and overlays the installed v151 schema in memory. Its preflight/report explicitly says whether it found an already-CP-shaped snapshot or used this overlay. An overlay validates SQL against CP's tables; it does **not** prove that the native DLL ran or that all native gameplay data matches a live activated session. The developer's archived fixture currently uses the explicit BNW-plus-schema-overlay mode.

Keep proprietary database snapshots outside Git. A workspace copy can live in ignored `dist/fixtures/`; public source downloads and their checksum manifest live in ignored `tools/reference/`. Generated reports from `audit_cp.py` now default to `tools/reference/CP-v151-audit.json`, not a released civilization asset. `--report` can select an explicit report destination.

## Windows PowerShell setup

Run from the repository root. Substitute your real Steam/library and snapshot locations:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt

$civUser = Join-Path ([Environment]::GetFolderPath('MyDocuments')) "My Games\Sid Meier's Civilization 5"
$env:CWC2_CIV5_USER_PATH = $civUser
$env:CWC2_CIV5_CACHE = Join-Path $civUser 'cache_backup\Civ5DebugDatabase.db'
$env:CWC2_CP_DIR = Join-Path $civUser 'MODS\(1) Community Patch'
$env:CIV5_PATH = "G:\SteamLibrary\steamapps\common\Sid Meier's Civilization V"

.\.venv\Scripts\python.exe tools/audit_cp.py --fetch
.\.venv\Scripts\python.exe tools/build_mod.py --manifest-only --preserve-art
.\.venv\Scripts\python.exe tools/validate_t1zofgk.py
.\.venv\Scripts\python.exe tools/validate_mod.py
.\.venv\Scripts\python.exe tools/audit_cp.py
.\.venv\Scripts\python.exe tools/build_mod.py --preserve-art
.\.venv\Scripts\python.exe tools/verify_release.py
```

Environment variables affect the current PowerShell process and its children. The snapshot path must already exist; these examples do not copy or modify a live cache. Use `CIV5_PATH` for the game **installation**, containing `Assets\UI\Styles.xml` and `Assets\DLC\Expansion2\UI\Civilopedia\CivilopediaScreen.lua`.

`audit_cp.py --fetch` downloads the complete shared inventory used by the collection, including T1's promotion/unit definitions and city-state gift code, at commit `44c1e14ff75d80c1dba5c8a71e8289439a53aafb`. The common configuration header comes from `CvGameCoreDLLUtil/include/`, while DLL sources come from `CvGameCoreDLL_Expansion2/`. A checksum manifest records the actual URLs and hashes. Missing, changed or incorrectly pinned references stop the dependent validator with the fetch command to repair them.

T1 validation also executes twelve synthetic prerequisite/read-only tests. Run those alone with:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tools/tests -p test_validation_prerequisites.py
```

For the corrective audit's before/after reproduction, retain Git history and run:

```powershell
.\.venv\Scripts\python.exe tools/validate_t1zofgk.py --compare-baseline 1d2ae91
```

This reads the original SQL and controller from that commit without checking it out, runs isolated Standard-speed regressions, then validates the current implementation at all four speeds. Only actual results are written to T1's `HardeningValidation.json`. Normal collection validation writes current results to `Validation.json` and does not invent a before/after result.

Working art is committed. No art generator, image service or unit model regeneration is required for this corrective audit. `--preserve-art` verifies framing while retaining the existing texture bytes.
