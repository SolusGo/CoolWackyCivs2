# The Boundless City — final engine investigation

**Baseline:** `7f88eaeb349f3bddf0027017f3983d7c8d8b1ea7` · **2026-10-12** · **1.2.0 preview / mod version 4** · **BNW + CP v151**

This release adds civilization-scoped survival, an original-capital siege reclaim action, protected-city subjugation, a native Domination finish, remote improvement development, explicit Tourism refresh and stronger extra-city route/border guards. The verified citizen model, art, expansion costs, Registry, Surveyor rewards and AI personality remain intact. No replacement DLL is included. The original collection was inspected read-only and retains its pre-existing project modification.

All new native calls are checked against official CP commit `44c1e14ff75d80c1dba5c8a71e8289439a53aafb`. [SourceAudit.json](SourceAudit.json) contains 176 assertions, 23 source URLs and hashes. Source inspection and nine Lua simulations establish API availability and mod decisions; **Civ V was not launched**. Native gameplay, UI layout, upgraded native trait caches and victory ordering remain outstanding. No limitation is labeled SOLVED on mock evidence alone.

## 1. Survival and original-capital reclaim

[CvPlayer::verifyAlive](https://github.com/LoneGazebo/Community-Patch-DLL/blob/44c1e14ff75d80c1dba5c8a71e8289439a53aafb/CvGameCoreDLL_Expansion2/CvPlayer.cpp#L33593) normally eliminates a founded civilization at zero cities even when units survive. Its existing `IsStaysAliveZeroCities` trait exception skips that specific branch. `getNumUnits()==0` and max-city-elimination rules still defeat the player. `setAlive(false)` kills remaining units and closes the slot, so an already eliminated player has no genuine army available to reclaim anything.

`TRAIT_BC_ONE_WORLD.StaysAliveZeroCities=1` activates that native exception only for Boundless. Complete Kills and other civilizations' trait rows are unchanged. There is no hidden city, forced resurrection, replacement capital or immortal zero-unit faction.

The military panel stays available when a living Boundless loses the Heart. Reclaim requires zero owned cities, saved coordinates and founding turn, original owner Boundless, native original-capital flag, visibility, war, 1 HP and an adjacent eligible melee unit with moves and attacks remaining. Air, embarked, defensive-only, busy/dead/delayed-death units are rejected; naval forces require a coastal city. Other native NoCapture promotions still prohibit reclaim; only the Boundless promotion is excepted by this special action. A second external city blocks reclaim until ordinary recovery resolves it.

The queue saves owner/founding/city ID, action and actor birth identity. Deferred execution repeats these checks, clears the queue before acting, consumes movement and calls `Player:AcquireCity(city, true, false)`. This binding invokes native conquest, which rebuilds the city, reinstates original-capital buildings, relocates invalid units and runs native capture effects. Unlike subjugation/demolition, reclaim can therefore have ordinary native conquest consequences. The city and actor are not dereferenced after acquisition. Capture hooks retire the old ledger; the fresh capital is resolved again, watch/ownership caches rebuilt, and preferences/progress/reward bits retained. Native handling determines which territory returns; the mod does not conjure all formerly owned plots.

**Why a panel action:** NoCapture is rejected before the opt-in `CanMoveInto` Lua event. Temporarily removing it around asynchronous movement/combat cannot guarantee that another settlement is never acquired. Normal attack-click recapture is still blocked. The special siege resolution is the useful safe partial path, and remains subject to native testing.

**Older saves:** [CvPlayerTraits::Read](https://github.com/LoneGazebo/Community-Patch-DLL/blob/44c1e14ff75d80c1dba5c8a71e8289439a53aafb/CvGameCoreDLL_Expansion2/CvTraitClasses.cpp#L7870) deserializes the cached survival flag rather than rebuilding it from the new SQL. Normal technology/policy processing rebuilds traits. A pre-v4 save may retain the old false flag until that occurs. No leader/policy/tech toggle is forced to refresh it: those operations can alter personality, rewards or other state. Test survival first in a new v4 game, then separately after a normal technology/policy refresh in an upgraded test save. An already eliminated v1–3 save is not revived by this release.

## 2. Conquest without occupation

[CvPlayer::canRaze](https://github.com/LoneGazebo/Community-Patch-DLL/blob/44c1e14ff75d80c1dba5c8a71e8289439a53aafb/CvGameCoreDLL_Expansion2/CvPlayer.cpp#L11666) rejects no-raze options, wrong ownership, human OCC and own-founded cities before its script hooks. Later code checks original-capital coordinates, holy cities, CP unique-civilization luxury protection and the final `CanRaze` veto. The current owner's early founding rejection prevents Lua from independently obtaining a complete later-rule decision. `Disband` is a destruction primitive, not permission. No bypass is added.

Native-legal 1-HP demolition still uses current-owner CanRaze plus hard original-capital/holy/current-or-original city-state exclusions. Native Disband runs outside combat/capture stacks and associated plots are released without releasing other city centers. Boundless receives no city, territory or custom capture reward.

If demolition is prohibited, an otherwise defeated **major** settlement can be subjugated once. Ownership, buildings, population, native capital control and territory stay as they are. It only spends melee movement and records the military result; it grants no Culture, Gold, yields, war-score bonus or repeat reward. City-state settlements and cities already razing stay unavailable. Capital and holy-city protection is visibly distinguished from demolition permission. No-raze options/vetoes still prohibit destruction, while a non-destructive acknowledgment is available.

The same saved original civilization, coordinates and founding identity cannot be subjugated again after transfer or liberation. New cities at a reused location do not inherit the former city's record. Queued actions cannot silently change from demolition to subjugation/reclaim if permission changes. Legacy queues remain demolition-only. AI uses the same checks at owner turns and deferred city-dirty/adjacent-movement events; no frame polling or extra map scan is added. Native tactical AI's choice to besiege these targets remains a gameplay test, not an implemented replacement strategy.

## 3. Citizen capacity proof

[CvCityCitizens::SetWorkingPlot](https://github.com/LoneGazebo/Community-Patch-DLL/blob/44c1e14ff75d80c1dba5c8a71e8289439a53aafb/CvGameCoreDLL_Expansion2/CvCityCitizens.cpp#L2206) requires a valid native city-array index; an arbitrary map index is not a valid citizen job. Local withdrawal produces a real forced default; the governor may freely reclaim other defaults. The City bindings expose neither arbitrary forced-default reservation nor a getter for that count. `TASK_SET_AUTOMATED_CITIZENS` is a no-op. Unassigned citizens and `TASK_ADD_SPECIALIST` with building -1 are not a safe substitute.

The existing pool remains `min(real defaults, max(verified forced withdrawals, max(0,P-M-Q)))`. F and surplus overlap. Fixtures retain 10/30, 30/150, 50/500 and 120/1,000 remote assignments at P10/40/80/150. At P80, all 80 ordinary citizens are still accounted for across native jobs/defaults/remotes; only the claim that all 80 can become remote is rejected. Native automatons are reported separately and suspend ambiguous remote credits. Six sources, normal Food consumption, growth and failure journalling remain unchanged. [OptionalDLLExtensions.md](OptionalDLLExtensions.md) proposes the minimal authoritative reservation API.

## 4. Worked effects

The six-yield system already reads evaluated plot yields and credits terrain once with default compensation. New `City:RefreshTourism()` directly invokes `UpdateCityYields(YIELD_TOURISM)` after terrain Culture changes or explicit rate refresh. Native landmark/improvement conversion therefore refreshes without a second Tourism credit. Removal and failure cleanup refresh it too.

`PlayerDoTurn` follows native city processing. Once per owner turn, validated assigned remotes that are outside native local positions and not `Plot:IsBeingWorked()` advance `ChangeUpgradeProgress(Player:GetImprovementUpgradeRate())`. Threshold uses `Game.GetImprovementUpgradeTime(improvement, plot)*100`; native SetImprovementType preserves builder attribution and handles the upgrade. The turn is persisted before mutation, so reload cannot advance twice. Removed assignments stop advancing; accumulated progress persists exactly as for an unworked native improvement. Completed upgrades trim/reconcile affected yields. Other players/unassigned plots get no adaptation. An interrupted update may skip remaining progress that turn, rather than risk replaying partial mutations.

The complete effect matrix, native counter dependencies, safe/unsafe building alternatives and live comparisons are in [WorkedTileEffects.md](WorkedTileEffects.md). This does not mark virtual plots natively worked or reproduce deterministic resource discovery.

## 5. Additional cities and quarantine

The audited `acquireCity` body has no pre-acquisition test veto; trade/gift/script paths can reach it directly. `CanMoveInto` is not a universal transfer guard. A native city can therefore exist before Lua dispatch. Recipients remain previous living legal owner → original living legal owner → native living liberation recipient → native-legal disband → quarantine. No arbitrary custodian or unsafe deletion is introduced.

New `PlayerCanCreateTradeRoute` is a native test-all veto in CvTradeClasses. Both origin and destination must be the genuine original if either player is Boundless. New `CityCanAcquirePlot` rejects native border selection by additional Boundless cities. Handlers use fresh immutable-original identity, so these restrictions apply before a pending quarantine record exists, and unrelated city pairs pass through. Already existing routes are not forcibly cancelled. Border-selection veto is not claimed to cover arbitrary scripted SetOwner or every purchase path.

Quarantine still clears production/automation, vetoes unit/building/project/process production, maintains resistance through native decrement, refreshes ordinary rates/purchases and excludes associated plots from remote work/Surveyors. It cannot universally erase strategic/luxury resources, Happiness, empire building/wonder effects, existing trade infrastructure, specialist **GPP**, total population/city counts, national prerequisites, bombard/rebase/access, native city UI or pre-dispatch rewards. Native specialist GPP processing is separate from the six city rates and is not universally stopped by resistance. Removing all buildings/resources or inventing negative empire offsets would damage return state or unrelated calculations. Absolute one-city ownership remains engine blocked.

## 6. The world bends before one city

`B.Config.SubjugationDomination=true` enables the optional civilization-specific finish; developers can set it false in BoundlessCore.lua to retain ordinary native victory-only play. The game must have Domination enabled, no prior winner/victory, a living Boundless owning only its genuine original, and at least one rival original civilization. Every ever-alive non-barbarian/non-minor **other-team** major counts, including eliminated rivals. Missing/unfounded/replaced originals block completion rather than being silently dropped.

Each required native original-capital plot must still resolve to the same original owner, civilization type, native capital flag and founding identity recorded by a genuine wartime siege. Current ownership/city ID may change through liberation or transfer without resetting progress. Teammates are excluded. Only successfully executed one-time subjugations count; queued/failed actions, peace, hidden cities and friendly capitals do not count.

[Game.SetWinner(team, VICTORY_DOMINATION)](https://github.com/LoneGazebo/Community-Patch-DLL/blob/44c1e14ff75d80c1dba5c8a71e8289439a53aafb/CvGameCoreDLL_Expansion2/Lua/CvLuaGame.cpp#L1431) calls the normal native CvGame winner setter, which records replay, broadcasts notifications and ends/extends the game through its existing manager. No global victory-valid flag, capital-ownership manipulation, foreign victory hook or custom manager is used. An existing result is never overwritten. Source supports this integration; live victory popup/save/achievement/scenario ordering remains **UNVERIFIED**.
