# Validation and CP v151 test guide

## Available validation

The tools run against a disposable in-memory copy of the installed BNW debug cache, upgraded with the installed CP table definitions. The user's cache, saves and installed mods are never edited. Python requires `lupa`, `Pillow` and `py7zr` from `requirements-dev.txt`.

Default development inputs:

```text
~/Documents/My Games/Sid Meier's Civilization 5/cache_backup/Civ5DebugDatabase.db
~/Documents/My Games/Sid Meier's Civilization 5/MODS/(1) Community Patch
```

`tools/database.py` accepts optional cache/CP paths for use by another developer; adjust the validator invocation in source or call that adapter with your paths if your installation differs. These caches are not redistributed. The committed SQL/art/manifests can be built and played without regenerating the database scripts.

Run from the repository root:

```powershell
python tools/build_mod.py --manifest-only
python tools/validate_mod.py
python tools/benchmark.py
python tools/build_mod.py
```

The checks cover:

| Check | Available result |
| --- | --- |
| Actual BNW/CP SQL execution | Passed; schema integrity, identities, correct native starting Settler, complete Worker/Monument companion inheritance, unchanged native rows |
| Unique effects and art registration | Passed; 3 Movement, 125% base WorkRate, +3 Registry Culture, no-annexing/no-capture, localization and existing atlas assets |
| Lua 5.1 syntax | Passed for every runtime, UI and test source |
| Native census simulation | Passed; real local/default/specialist census, assigned yields, labourer subtraction and no population inflation |
| Lifecycle simulation | Passed; growth/starvation, plot loss, pillage-yield changes, water/blockade/mountain rejection, release, reload, older snapshots and one-time improvement rewards |
| Frontier simulation | Passed; contiguous claims beyond thirty hexes and across water, enemy protection, speed scaling, Registry cap, cached ownership and no yields from unworked territory |
| Ownership simulation | Passed; promotion assignment, extra Settler cleanup, deferred transfer ordering and original-capital protection |
| UI simulation | Passed; launcher/panel, paged instances, city/diplomacy/popup hiding, Escape and no permanent frame update |
| Package/project | Passed; exact file inventory, SQL order, VFS flags, manifest hashes, XML/control references and all 34 decoded DDS textures |
| ZIP/Civ5Mod | Generated by the pure-file builder; Civ5Mod is genuine 7z/LZMA and archive integrity is checked |
| Native gameplay, save/load, FPS | **Not run** |

The Lua mock enforces its own census and native task semantics rather than assuming free workers. It still cannot reproduce all CP governor, pathfinding, save or capture internals. The [API audit](APIAudit.md) explains which behaviors were checked in C++ source and which alternatives were rejected.

## Performance

`tools/benchmark.py` processes a synthetic **16,000-plot**, 40-Population wrapped map, including 20 full forced workforce reconciliations. The measured output is [Benchmark.json](Benchmark.json). The initial run measured roughly 254 ms initialization and 52 ms median full reconciliation in the Python/Lua mock. Those numbers measure this host and mock calls, **not Civ V turn time or FPS**. Later runs replace the JSON with their own actual timings.

There is one initial map scan per Boundless player, ownership-event cache maintenance, component walks after topology changes, turn-based candidate scoring and sixteen-row UI pages. The one-shot dispatcher unregisters itself before doing work. Repeated unchanged city-dirty events stop at a signature check. No 0.1-second whole-map scan, recurring update loop or CityView override is used.

Real Huge-map testing must measure turn-time impact, UI-open/closed FPS, idle behavior and ScriptData/save size separately. Do not infer native performance from the microbenchmark.

## Exact in-game setup

1. Back up saves. Install BNW and Community Patch v151, then extract the built ZIP's `Cool Wacky Civs 2 (v 1)` folder into the normal `MODS` directory.
2. Enable logging in the game's configuration (`LoggingEnabled = 1`, `AILogging = 1` if investigating AI). Launch through **Mods**, enable CP and this collection, and start a new single-player game.
3. Select **The First Architect / The Boundless City**. First use Standard speed on a small map; later repeat on Epic/Marathon and a Huge wrapped map.
4. Confirm the leader/Dawn illustration, navy/gold colors, icons, initial Settler, Surveyor replacement and Registry appear. Found **The Heart of the World**.
5. Inspect `Logs/Database.log` and `Logs/Lua.log` after mod activation and founding. Resolve SQL/Lua errors before interpreting gameplay results.

## A — civilization loading and uniques

Verify one civilization/leader entry, Civilopedia text, Worker build commands/automation and the actual active Monument costs/prerequisites. Build/purchase the Registry. Its base Culture should be 3; at 10/20/100 owned plots the bonus should be 1/2/10, with no duplicates after load. Pillage/repair should not repeatedly grant Surveyor Culture. Time an ordinary Worker and Surveyor on the same Build with identical modifiers: base work points should differ by 25%, while discrete turns may tie.

## B — territory beyond the native rings

Use FireTuner or an in-game editor in a separate test save to provide Culture and reveal the map. Keep a record of owned plots at turns 1, 10, 30 and 60. Confirm expansion past five rings and past thirty hexes. Cross water into a new landmass through successive adjacent claims. Place enemy-owned tiles on the boundary: they must not be stolen. Repeat at map edges and on X/Y wrapped map types. Try each direction preference and verify stable tie resolution after reload.

Ordinary Social Policy Culture and Tourism must retain their normal rates/storage. Frontier claims must consume only the custom progress pool. Save immediately before a claim and repeat the turn after loading: ownership/progress should be identical.

## C — distant yield arithmetic

Create distinguishable local and remote plots. Set remote management to Manual. Record population, local workers, default labourers, specialists and all six capital yield rates before/after each assignment. Assign a farm at distance 12, mine at 20, trading post at 30 and fishing improvement across a coastline.

Each assignment must remove one local worker, create one default labourer and credit precisely the remote plot yield while subtracting that labourer's evaluated yields. Effective population and food consumption must not increase. Release the assignment: its yield contribution must disappear and the worker return to native allocation. Owning 300 unworked plots must not inject their yields.

Repeat with a city modifier, specialist-yield policy and Golden Age to identify native worked-state effects listed in the limitations guide. Do not assume unsupported worked-only Tourism or counters are implemented.

## D — workforce lifecycle and modes

Test population growth, starvation, an editor-induced population loss, manual specialist changes, native city-center reset, new technologies, policy/religion changes, pillage/repair, visible enemy occupation, water blockade and lost territory. Inspect the synchronous trim and next deferred reconciliation. Assign beyond the available native reservation capacity: no free worker may appear, and excess locks must remain pending.

Compare Automatic with Food/Production/Gold/Balanced priorities. Hybrid must preserve legal locks before other choices; release must exclude the plot. Manual must not choose unrequested remote plots. Native governor specialists remain part of the census. Reopen the panel, page/sort rows, locate a plot, enter diplomacy/city screens, trigger duplicate popup notifications and press Escape. No launcher should remain obstructing an incompatible screen.

## E — ownership and conquest

Confirm production, purchase, gifts, capture and scripted creation of Settlers cannot create an additional normal settlement. All acquired military units must carry NoCapture. Attack an ordinary enemy city, major original capital, city-state capital and holy city: normal occupation must be blocked and protected cities must remain intact.

Then deliberately transfer a city through diplomacy/editor/native script. Verify recovery runs after acquisition rather than recursively destroying a city inside its hook. Check recipient preference, a dead former owner, multiple simultaneous transfers and two Boundless players. The original capital must never be returned. Test a save around deferred recovery. If there is no eligible living recipient, expect documented quarantine, not an illegal deletion; that case proves the remaining strict one-city design gap.

Test original-capital loss and reclaim. Confirm that remote yields do not leak to its captor and no substitute city activates the UA. Audit the native capture popup and city-selection ordering for a briefly usable transferred city. This is not yet certified.

## F — AI and victories

Run an AI Boundless player for at least 100 turns, including at least one era transition. Record frontier counts, food balance, remote assignments, Surveyor targets/path completion and military acquisitions. Confirm it never trains Settlers and can develop distant districts in its current land area. Audit whether native homeland AI overwrites queued missions; test island starts and disconnected areas separately. No other civilization should use the custom workforce.

Verify Science projects, Culture/Tourism and Diplomatic voting with normal rules. Domination should remain governed by normal foreign-capital ownership and is unavailable to the usual one-city/no-capture strategy; there is no alternate victory implementation.

## G — Huge-map and regression

On a Huge late-game map, compare turn time and FPS with this mod enabled/disabled, with the workforce panel closed/open and with several thousand owned plots. Record hardware, mod roster, counts and save size. Dirty events should not keep an update callback alive while state is unchanged.

Enable the separate original collection and play non-Boundless civs, including The Last City, The Kingdoms and The Shattered Empire. Confirm their UI/save mechanics remain independent. Source-file separation and original-folder status were checked; combined live gameplay regression has not been performed.

Archive the actual native logs and results before upgrading this preview to a stable release.
