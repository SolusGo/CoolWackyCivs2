# Exact remaining engine restrictions

Release 1.1.0 / mod version 2 is an implementation preview. Source audits and mocks support the design decisions below; no native Civ V session has verified them.

| Requirement | Current behavior and remaining restriction |
| --- | --- |
| Unlimited cultural distance | Cached capital-connected frontier claims, including water/wrapping, with no mod radius/tile cap. Finite map size and native ownership rules still apply. |
| Unlimited remote distance | Any-distance owned, yielding, non-city plots meeting enemy/blockade/water-tech checks can be selected. Virtual plots are not marked natively worked. |
| Population-only remote count | **Partial.** Real forced withdrawals plus a conservative surplus support 50 remote workers at population 80/native jobs 30 and 120 at population 150. They do not permit all 80/150 remotely: CP exposes no arbitrary forced-default setter or safe governor automation disable. Building slots/local locks/specialists reduce capacity; unassigned citizens are not invented as defaults. |
| Exact citizen accounting | Each credited remote plot consumes one protected real default; local + remote + building specialists + idle defaults + genuinely unassigned = population. Center is free. Positive external automatons disable remote credits. Governor/event/cached-rate order still requires native testing. |
| Six yield sources | Food, Production, Gold, Science, Culture, Faith: gross terrain source minus default compensation through misc, modifiers once. Both sources and refresh pulses are journalled. |
| Native worked-tile effects | **Partial.** Terrain-Culture source conversion to Tourism is represented, but immediate Tourism cache refresh, worked terrain/improvement/resource counts, worked-only Tourism, conditional worked requirements, improvement development and arbitrary custom yields are not fully reproduced. Native remote plot recalculation after Golden Age/religion/policy changes needs testing. |
| General military conquest without occupation | **Unmet.** NoCapture prevents occupation. Restricted 1-HP siege demolition applies only where the current owner can legally raze, generally already captured settlements. First-founded enemy towns cannot be legally certified by the exposed ownership-dependent CanRaze API. |
| Capitals/holy cities/city-states | Hard exclusions in addition to native CanRaze. No resurrection/automatic liberation of protected enemy cities without acquisition. They remain intact. |
| Absolute immediate one-city guarantee | **Unmet against external transfers.** Normal founding, Settler production, buyout and capture are blocked. Other mods/diplomacy can acquire a transient city before deferred recovery. Historical/native living recipients are used; legal orphan extras can be removed. Own-founded/protected no-recipient extras remain quarantined, with queues/automation and production requests blocked. They may still have native yields or UI effects. |
| Original capital | Coordinates + founding turn remain fixed; native original-capital identity is required at initial recognition. Loss suspends the UA. No replacement Palace activates it. A matching legal transfer can restore it; NoCapture also prevents ordinary military recapture. |
| Domination | Foreign original capitals cannot normally be occupied; no alternate victory/global rule change is supplied. Science/Culture/Diplomatic rules remain native and unverified in-game. |
| AI and performance | Shared rules, cached builder candidates, rotating checks and real pathfinding. Later homeland-AI interference, ocean development, path completion, native save size and Huge-map FPS remain untested. No distance cap or teleport workaround. |
| Save compatibility | Version 1 state/BCY1 migrate forward explicitly. Unknown/corrupt state disables custom operation while preserving its payload; only verified ledger contributions can be removed. No downgrade guarantee and no recovery from an externally corrupted source ledger. |

Native city source recalculations or arbitrary other mods can invalidate Lua assumptions without a complete event notification. Events, synchronous trimming and mandatory owner/end-turn renewal are the available defense, not a proof of correctness under every external mutation. Unit deaths and unexposed state changes have turn-based fallback recovery.

The repository contains no custom DLL, hidden city, radius increase, population inflation, negative automatons or passive yields from unworked land. Full arbitrary citizen reservation and safe general conquest resolution require additional native interfaces. Do not remove these restrictions from the release description until actual native regression tests establish the stronger behavior.
