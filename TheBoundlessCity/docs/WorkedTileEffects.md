# Native and virtual worked tiles — CP v151

Local jobs are native citizen-array jobs. Remote jobs consume protected real default citizens but remain **virtual worked plots**: their evaluated yields enter the capital terrain source, and native Plot:IsBeingWorked normally stays false. Neither all owned land nor a UI selection by itself produces a worked effect.

Sources below use official commit `44c1e14ff75d80c1dba5c8a71e8289439a53aafb`; hashes/URLs are recorded in [SourceAudit.json](SourceAudit.json). New adaptations require native gameplay verification.

| Effect | Category | Native dependency / implementation |
| --- | --- | --- |
| Evaluated terrain/resource/improvement yields, ordinary policy/trait/tech/route/adjacency/Golden Age changes already present in GetYield | Already represented | CvPlot yield calculation and Lua GetYield; credit six evaluated yields once. Some city/religion context and recalculation timing remain native tests; do not add another blanket policy/GA multiplier. |
| City modifiers on six yield rates | Already represented | Terrain/misc source arithmetic applies native city modifiers once; defaults compensated. |
| Landmark/improvement Culture conversion to Tourism | Safe Lua adaptation, implemented | CvCity Tourism calculation reads GetBaseYieldRateFromTerrain(CULTURE). City.RefreshTourism invokes UpdateCityYields(TOURISM). No second Culture/Tourism adjustment, dummy building or guessed multiplier. |
| ImprovementUpgrade progression | Safe Lua adaptation, implemented | CvCity.doTurn calls CvPlot.doImprovement only for local native working entries. Remotes get one native-rate progress step per owner turn; plot-specific native threshold and SetImprovementType(builder) finish it. Already natively worked/local plots excluded, so no double advancement. |
| Removal/population loss/reload for these adaptations | Implemented lifecycle | Existing trim/reconcile removes invalid yields and refreshes Tourism. Only current validated assignments advance. Persisted developmentTurn precedes mutations; unassigned plots keep previous development, as native unworked plots do. |
| Worked terrain/feature/featureless/improvement counters and per-X city/religious bonuses | Native integration required | CvCityCitizens.SetWorkingPlot changes internal arrays and ChangeNum*Worked counters. Those counter mutators are not registered in City Lua. GetYield is insufficient for city-level count formulae. |
| Worked-resource/river/terrain queries, third-party HasWorked/CountWorked/IsWorkingPlot/IsBeingWorked | Native integration required | Queries traverse native citizen positions or vectors. A dummy building cannot make a remote plot satisfy these queries. Arbitrary native index insertion violates SetWorkingPlot's local-index preconditions. |
| Great Person rate from worked improvements | Native integration required for general compatibility | CvCity.GetImprovementGreatPersonRateModifier loops GetWorkedPlots, excludes pillaged improvements and adds each improvement's modifier. No direct City Lua mutator for this source. A finite dummy-building modifier could approximate this one numeric bonus, but needs a separate persistent building journal and would still fail all worked queries; not shipped as general equivalence. |
| Building per-X terrain/feature yields and conditional policies/traits/beliefs/events | Native integration required for general compatibility | Native count/rounding/context and worker changes determine results. Ad hoc six-yield/building copies risk double-counting or diverging at thresholds. |
| Resource discovery from worked improvements | Not safely reproduced fully | CvPlot.doImprovement uses native revealed-resource checks, deterministic CvSeeder/plot pseudo-random input, native map resource quantity and notifications. Copying random chances through Game.Rand would change native RNG semantics. No exposed doImprovement wrapper verified. |
| Worked-only Tourism beyond terrain Culture conversion | Native integration required | New RefreshTourism recalculates existing native source formulae; it does not populate missing worked counters, direct custom yield types or external-mod triggers. |
| Worked animation, yield display, automation/path value and replay worked-tile dataset | Native integration required | CvPlot.isVisibleWorked/layout and CvPlayer replay count depend on native worked status. The custom workforce UI remains the authoritative remote assignment display. |
| Safe dummy buildings/promotions | Narrow adaptations only, none new | Existing finite Registry bits represent its territorial Culture rule. Neither promotion nor building grants an authoritative exclusive citizen reservation or makes arbitrary plots worked. No unlimited buildings, fabricated specialists or passive owned-tile effects are added. |

For a live comparison, use equal local and remote improved plots. Record Plot:GetYield, terrain/misc sources, six city rates, base Tourism, native CountNumWorkedImprovement, GP rate and upgrade progress. Assign, release, starve, reload, pillage and change policy/religion/Golden Age. Expect equal supported arithmetic/progression and explicitly different native worked queries. If the city context gives different Plot:GetYield, record that as a further native-context limit rather than adding a blanket correction.
