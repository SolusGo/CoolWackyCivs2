# Implementation and compatibility

`SQL/00_PIGEON_Core.sql` creates the civ, leader, trait, replacement identities and city/spy names. Scalar inheritance uses a temporary `SELECT *` copy at database activation, so the active Scout/Caravansary CP values and additional columns survive. `01_PIGEON_Inheritance.sql` copies every known companion table with `UnitType`/`BuildingType`, including upgrades, AI roles, free promotions, resources, prerequisites and flavors. Regenerate this table inventory with `tools/generate_pigeons.py` when targeting another schema. New companion tables from other mods unknown at generation are outside this guarantee; a mod that changes the baselines after this collection loads cannot retroactively change the copies.

`02_PIGEON_Effects.sql` adds the lookout promotion, additive Culture, three dummy types, leader flavors and diplomacy responses. `03_PIGEON_Art.sql` registers the atlases; `10_PIGEON_Text.sql` registers English localization. Every database identifier uses the PIGEON namespace. Native types are read without changing their mechanics. CP event options enable City, new-era, route-completion and route-plunder hooks, whose Pigeon handlers are scoped. There are no DLL/game-file edits.

`UI/PigeonTrade.xml` is a separate, invisible InGameUIAddin context that owns `PigeonTrade.lua`. The manifest and ModBuddy register it once. SQL and entry XML remain outside the VFS; paired Lua, leader scene and all DDS assets are imported. The builder enumerates both civilization directories and loads each SQL set in numeric order. Mod version 5 retains the collection UUID and minimum compatible version 1, without changing any Boundless gameplay or persistence data. Existing saves still need native upgrade testing.

The Lua reads `player:GetTradeRoutes()`, compares `route.Domain` with `DomainTypes.DOMAIN_LAND`, checks `route.FromID` and `route.FromCity:GetOwner()`, and groups counts by `FromCity:GetID()`. It checks that each origin still resolves through `player:GetCityByID`. Names, destinations and route paths never determine eligibility. The per-route amount is 2 before `ERA_RENAISSANCE`, otherwise 3; it never scales with game speed. Every current city gets exactly `routeCount * perRoute` copies of the +1 Science and +1 Culture dummies. The +2 Production dummy count is exactly 1 when the Pigeon owner has a Roost and an outgoing land route, otherwise 0.

`SetNumRealBuilding(building, amount, true)` sets absolute counts and suppresses construction rewards; unchanged counts produce no writes. CP v151 processes the difference in real building counts and multiplies base yields by that difference. Dummies have Cost/FaithCost -1, IsDummy 1, ShowInPedia 0, GreatWorkCount -1, NeverCapture 1, ConquestProb 0, no upkeep and their own unrestricted classes. They cannot enter ordinary build/purchase selection, and native capture drops them. Initial/load cleanup, capture recipient cleanup and non-Pigeon turn cleanup remove residual counts even after a scripted transfer.

PlayerDoTurn is the authoritative fallback for humans and AI. Additional verified hooks cover trade completion, plunder, trade-unit consumption, construction/sale, capture and team era. BNW/CP WarStateChanged and SerialEventGameDataDirty cover other route changes. UnitPrekill observes the caravan consumed after CreateTradeRoute succeeds. CP's completion hook occurs **before** ClearTradeRoute, so event handlers queue IDs and a one-shot ContextPtr update reads current state after native return. The callback calls ClearUpdate before work and removes itself even on a refresh error. Dirty storms coalesce; synchronous self-generated dirties are ignored during writes. There is no idle frame callback, timer or constant UI update.

No city userdata or route counts persist between refreshes. Capturing or razing an origin/destination schedules recomputation from current owners; elimination yields no routes. Context creation scans all owners for cleanup, then normal data dirties refresh configured Pigeon slots only. Dead city objects are never cached. Save/load reconstruction uses native buildings, routes and eras, without ScriptData or transient counters as authority.

Event-driven refresh is deferred until native return; UI displays can update on the next dispatched callback. Mods that silently mutate buildings/routes without events reconcile on PlayerDoTurn. Native turn yield timing, save reconstruction and unusual scripted ownership operations must still be tested in Civ V. Standard resistance/razing and yield modifiers govern the resulting base yields.

API behavior was checked against [official CP source at commit 44c1e14](https://github.com/LoneGazebo/Community-Patch-DLL/tree/44c1e14ff75d80c1dba5c8a71e8289439a53aafb/CvGameCoreDLL_Expansion2), whose CustomMods.h identifies DLL v151. `SourceAudit.json` records 14 route/building/event contracts and file hashes. The installed CP XML/SQL and read-only backup BNW cache provide the schema. See [Testing.md](Testing.md) for scope and results.
